# Deploying BijliSaver — free-tier stack

- **Database** → Neon (free forever, no expiry, standard Postgres)
- **API + OCR service** → Render free Docker web services (sleep after 15 min
  idle, ~1 minute cold start on the next request — fine for low traffic)
- **Frontend** → Render free Static Site (no sleep — it's just files on a
  CDN, not a running container)

Render deploys from a connected GitHub repo, not from a local `docker build`
like Fly does — so step 1 is getting this code onto GitHub. Everything below
needs your own Neon/GitHub/Render accounts, so these are commands and steps
for you to run — I can't create accounts or type secrets into anything on
your behalf.

## 1. Push this repo to GitHub

```powershell
cd D:\Projects\BijliSaver
git init
git add .
git commit -m "Initial commit"
```

Then create a new repo at https://github.com/new (public or private, your
call) and push:

```powershell
git remote add origin https://github.com/<your-username>/BijliSaver.git
git branch -M main
git push -u origin main
```

## 2. Create the Neon database

1. Sign up at https://neon.tech (free, no card required for the free plan).
2. Create a project — any region close to Pakistan works (Singapore is
   closest).
3. Copy the connection string it gives you (starts with `postgresql://`).
   You'll paste this into Render in step 4.

## 3. Create the Render Blueprint

1. Sign up at https://render.com and connect your GitHub account.
2. Dashboard → **New** → **Blueprint** → pick the repo you just pushed.
   Render reads `render.yaml` from the repo root and proposes all three
   services (`bijlisaver-api`, `bijlisaver-ocr`, `bijlisaver-web`)
   automatically.
3. Click through — it'll ask for the env vars marked `sync: false` in
   `render.yaml` before the first deploy (next step covers what to put in
   them).

## 4. Fill in the secrets

When Render prompts for them (or afterward, under each service → **Environment**):

- **bijlisaver-api** → `DATABASE_URL` = the Neon connection string from step 2
- **bijlisaver-ocr** → `OPENAI_API_KEY` = your new rotated Gemini key from step 0

`Jwt__Key` is auto-generated by the blueprint (`generateValue: true`) — you
don't need to set it.

## 5. Deploy

Render deploys automatically once the blueprint is applied. Watch the build
logs for each service in the dashboard. First deploy takes a few minutes
(Docker builds for API/OCR, `npm run build` for the frontend).

## 6. Verify

Open `https://bijlisaver-web.onrender.com` (or whatever Render assigned —
check the dashboard if the name was taken). Upload a real bill and confirm
it comes back with a full breakdown. If the API or OCR service was asleep,
the first request will take ~30-60s to wake it up — that's expected on free.

If something's off, check logs per-service in the Render dashboard, or:

```powershell
curl https://bijlisaver-api.onrender.com/api/bills
curl https://bijlisaver-ocr.onrender.com/health
```
